# FogVault 0.1.0

Release date: October 30, 2026.

FogVault provides an independent Rust vault engine with native SQLite storage and
a browser Worker/WASM SDK backed by IndexedDB. Native and browser entry points
share lifecycle and authorization logic in the portable Rust core. The supported
behavior and limits are defined by the [maintained delivery contract](../maintained.md).

## Packages

- Rust: `fogvault`, `fogvault-native`, and `fogvault-backup`, each 0.1.0.
- Browser: `@datafog/fogvault-browser@0.1.0`, including its Worker, WASM and TypeScript types; npm metadata identifies this GitHub source for publishing provenance.
- Backup dependencies retain five separately named, provenance-preserved forks:
  `fogvault-age@0.11.5`, `fogvault-i18n-config@0.4.8`,
  `fogvault-i18n-embed-impl@0.8.4`, `fogvault-i18n-embed@0.16.0`, and
  `fogvault-i18n-embed-fl@0.10.1`. These expose only FogVault's supported feature
  closure; their names do not imply general upstream feature parity.

FogVault is independently versioned. DataFog Core's 1.0.0 release does not rename
FogVault to 1.0.0. Compatibility with the exact published Core 0.5.0-beta.3 remains
an explicit regression alongside the Core 1.0 integration checks.

## Verification and scope

The shared verifier checks native and browser lifecycle behavior, wrong passwords,
tampering and transaction outcomes, including the installed package consumers.
The registry preflight verifies all eight Rust archives through a fresh local
registry-only consumer, preserves the approved dependency identities, validates
retained upstream advisory evidence, and admits the actual browser tarball.
Publication additionally requires registry dry runs and fresh public-registry
installation checks described in the [release procedure](../packaging.md#release-procedure).

These results do not claim independent implementation certification, physical
mobile-device or power-loss qualification, Safari/WebKit qualification, or shipping
extension/provider acceptance. Applications remain responsible for their host
security, platform key providers, and the documented resource/admission limits.
